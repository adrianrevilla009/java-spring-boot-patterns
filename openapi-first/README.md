# openapi-first

An Orders contract in `src/main/resources/openapi.yaml`, a Maven build step that generates the Spring interface and models from it, and a hand-written `OrdersController` in `App.java`.

## Goal

Write the API contract first and generate the controller interface and DTOs from it at build time, so the code cannot drift from the spec.

## Run it

```bash
./mvnw -q test
```

Expected: `ContractTest` passes with no failures. Generated sources appear under `target/generated-sources/openapi`. The first run needs network access to Maven Central.

## What it proves

- `OrdersApi` (interface) and `NewOrder` / `Order` (models) are generated by openapi-generator-maven-plugin 7.12.0; `OrdersController` only implements behaviour.
- A constraint in the spec (`quantity` with `minimum: 1`) becomes a Bean Validation annotation on the generated model, so `quantity: 0` returns 400.
- Routes and status codes follow the spec: 201 on create, 404 for an unknown id.

## Trade-offs

- The generator runs with `interfaceOnly` and no springdoc or swagger annotations, to keep generated code and dependencies small.
- The contract becomes the reviewed source of truth, but generator output (naming, templates) changes between versions, hence the pinned plugin.
- Spec and implementation can still disagree on behaviour the spec cannot express; contract tests are needed for that.
- Orders are stored in an in-memory map.

## When not to use it

- Small internal services with one consumer, where code-first is quicker.
- Exploratory APIs that change every hour.
